# XClub Fantasy — League Hub Worker

Weekly hub for the **Tom Byrne Memorial FF League** (Sleeper `1371971946459201536`, 12-team standard).
Live at **https://xclubfantasy.robsplex.com** (Cloudflare Worker + static assets + KV).
Built mobile-first: most readers use it on a phone, so the phone layout is the primary target.

## Architecture
- `src/index.js` — Worker. Serves static assets and assembles `/api/data` from the Sleeper
  public API (league, users, rosters, matchups, projections, trending, transactions) plus
  `public/data/history.json`. Adds power rankings/all-play, all-time H2H rivalries (flagged
  when renewed this week), draft-return report, and the editorial payload. Caches JSON in KV
  (`XCF_KV`). No credentials are used — everything is public, read-only.
- `src/domain.js` — pure calculation layer (rosters, projections, bench swaps, standings,
  completed-week logic, editorial assembly). Imported by both the Worker and the tests.
- `public/index.html` + `public/styles.css` + `public/app.js` — dependency-free client
  (no framework, no Tailwind CDN). Views: Home / Hype / Scores / Standings / Teams /
  Players / Injuries / Wire / History, fixed bottom navigation under 1000px, full-screen
  article reader, client-side filter, sort, and pagination for the 880-player pool.
  Day / Night Edition theme toggle: theme lives on `html[data-theme]`, persisted to
  `localStorage["xcf-theme"]`, defaults to system `prefers-color-scheme`, and is applied
  by an inline `<head>` script before first paint (no flash). All colours are CSS custom
  properties with a dark value; the print stylesheet forces the light palette. The Hype
  view (`#weekend`) is narrative and leads with a **Matchup of the week** deep-dive
  (`payload.featured`, from `featuredMatchup()` in `domain.js` — the closest projected
  finish pre-game, the closest actual margin in a recap, chosen deterministically from the
  same data-only narrative cards). The **Injuries** view (`#injuries`) renders
  `payload.injuries` (`injuryDesk()`) as a severity-sorted, position/team-filterable
  table. The **Wire** view (`#waivers`) surfaces completed waiver claims, adds/drops and
  trades (`payload.waivers` from `waiverDesk()` in `domain.js`) plus the league trade
  deadline and each team's remaining FAAB, all filterable by type/position/week/team.
  Installable as a PWA: `public/manifest.json` + maskable/any icons (built by
  `scripts/make_icons.py`) + `apple-touch-icon.png`; `theme-color` follows the active theme.
- `public/data/players.json` — compact player bundle (name/pos/team/injury for the whole
  league pool). Generated by `scripts/build_players.py` from the 14MB `/players/nfl` dump —
  **rerun when rosters change**, then redeploy.
- `public/data/history.json` — 5-season league chain (2022–2026), per-season tables,
  all-time H2H by owner uid, verified playoff champions. Built by `scripts/build_history.py`
  from `/winners_bracket` — rerun after each season. The current season is never frozen in;
  the Worker adds live matchups.
- `wrangler.jsonc` — custom domain `xclubfantasy.robsplex.com`, KV binding, hourly cron.
- The Worker 308-redirects fragment-less deep links (`/game/2/1`, `/team/3`, `/story/…`,
  and view names like `/home`) to their canonical `/#…` form, so links that lose their `#`
  (typed in, or forwarded through a handler that strips it) still resolve instead of 404ing.
  The `#game/WEEK/MID` route always scrolls to and opens its card, whether reached by click
  or as a shared deep link on first load.
- `public/_headers` — CSP and hardening headers (CSP allows images from `sleepercdn.com`
  only, alongside `self`).

## Editorial rules (learned the hard way)
- No fabricated quotes, "sources close to", or invented injury explanations. Every claim
  traces to a box score, lineup, draft pick, or transaction record.
- Champions come from the playoff `winners_bracket`, never from a regular-season table.
- Bench comparisons only count swaps that are legal in this league's slots (e.g. a WR cannot
  replace a QB), so "points left on the bench" is actionable rather than theoretical.
- Raw projections may cover only part of a lineup; state coverage instead of implying a
  complete projection, and show a dash (not zero) when a value genuinely does not exist.
- Only completed transactions are shown; no future-dated noise.

## Data freshness
- Cloudflare cron `17 * * * *` (hourly) force-rebuilds the KV league payload — covers Thu/Sun/Mon game windows.
- **Live auto-refresh (game days):** while a game window is `in_progress` the Worker
  only trusts its cached payload for five minutes and accepts a forced
  `?refresh=1` rebuild every five minutes (shorter than the usual ten-minute
  throttle). The client polls `/api/data` on the cadence the payload reports in
  `refresh_window` (2 min live / 15 min otherwise), silently, and only while the
  tab is visible and idle. So on game days the site is at most ~5 minutes stale
  without anyone tapping Refresh.
- Hermes script-only cron **XClub Player Metadata Refresh** runs daily at 8:00 AM America/Toronto. On this native-Windows host it uses
  `xclub_player_metadata_refresh.py` (not the Git-Bash/WSL `.sh` convenience wrapper). It fetches the
  live Sleeper `/players/nfl` dump, atomically rebuilds `public/data/players.json`, verifies every
  numeric bundle record's NFL team/injury/position fields against the same Sleeper snapshot used
  to build it, deploys only the validated artifact, and checks the production timestamp. Success is
  silent; failures alert.
- `GET /api/data` serves KV cache; `GET /api/data?refresh=1` force-rebuilds, rate-limited to
  once per 10 min (KV key `last_build_ts`).
- The payload cache key includes both the `BUILD` const and the imported player-bundle timestamp,
  so a metadata deployment cannot reuse a payload generated with the prior static bundle.
  Bump `BUILD` in `src/index.js` after code changes that alter payload shape, and bump the `?v=`
  query on `styles.css` / `app.js` in `index.html` so returning phones pick up new assets.

## Weekly league digest (Discord)
A fully factual, script-only digest — no LLM, no credentials. `scripts/weekly_digest.py`
polls the public `/api/data` until the latest league week is fully scored (it re-checks every
5 min for up to 60 min, because Monday Night Football can score after midnight), then builds a
single Discord message from: the scoreboard, top-5 standings, the weekly awards, top performers,
a next-week preview (closest projected finish + projected stars), the injury watch, and waiver
wire moves. Every number traces to the league payload; nothing is invented.

- **Delivery:** two Hermes script-only (`no_agent`) cron jobs run the native entrypoint
  `xclub_weekly_digest.py` (a thin `runpy` wrapper around the script). The primary job fires
  **Sunday 23:15 ET** (`15 23 * * 0`); a **Monday 08:00 ET** catch-up job (`0 8 * * 1`) handles
  any week whose scores finalized late. Both deliver to the origin Discord channel.
- **Exactly-once:** a `digest_state.json` ledger (gitignored) records which week/season pairs
  have been delivered, so the Sunday + Monday pair never double-posts.
- **Silent on no-op:** under `no_agent`, empty stdout means the week is not yet deliverable or
  was already sent — the runner stays quiet. Non-zero exit (fetch/build failure) surfaces an
  alert. Success on a delivered week prints only the digest text.
- **Manual preview:** `python scripts/weekly_digest.py --dry-run` builds and prints the digest
  from *current* data immediately (no waiting, no state write) — use it any day to see the shape.
- **Degradation ladder:** the builder trims sections (injuries, then moves, then preview detail)
  to fit Discord's 2000-char limit, always preserving the scoreboard + factual disclaimer.

## Sleeper API notes (verified 2026-09-16)
- League is standard scoring → use `pts_std` in stats/projections.
- DEF pids: rosters use plain abbr (`KC`), stats/projections use `TEAM_KC` — normalized in
  `norm_pid()`; the bundle stores DEF under plain abbr.
- Standings come from roster `settings` (fpts + fpts_decimal); points are hundredths, so
  `fpts + fpts_decimal/100`.
- Week completion authority is `league.last_scored_leg`, not the NFL state week.
- Trending endpoint: `/players/nfl/trending/add?lookback_hours=168&limit=N`.
- Matchup IDs (`matchup_id`) are NOT unique across weeks — the same mid can exist in both
  the completed and upcoming slates. Any shareable game link must be week-qualified
  (`#game/WEEK/MID`); a bare `#game/MID` resolves recap-first, then preview.
- `team_form` / `season_top` in the payload are keyed by **roster_id**, not manager uid.
  Draft picks carry the owner's roster_id in `rid`; transactions already use roster_id.
  The team page (`#team/{rid}`) deep dive renders: season form strip (tap a week → its box
  score), season top-5 scorers, draft picks, and on-the-wire transactions.
- Injury statuses in player metadata are full words ("Questionable", "Injured Reserve",
  "PUP"), not abbreviations — `injuryRank()`/`injuryChip()` in `domain.js` normalize them;
  unknown statuses rank last but still display (chip `?`).
- Sleeper's CDN blocks team logos (use coloured chips/abbreviations); player headshots work
  at `https://sleepercdn.com/content/nfl/players/{pid}.jpg`.
- `wrangler.jsonc` sets `run_worker_first: true` so the Worker intercepts `/` and `/weekend`
  and injects live `og:title`/`og:description` into the HTML (link preview cards for
  WhatsApp/Discord). The Worker reads the HTML via `ASSETS.fetch` — `ASSETS.get` returns a
  Response in production and must be `.text()`-ed, never `.value`-ed.
